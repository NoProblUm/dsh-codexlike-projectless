# 本地第一版｜插件阶段与诊断日志

直接修改本地 v0.6.0 源码，不另建仓库，不修改本机 DSH 安装或 profile。本版是详细设计中的插件验证阶段，不是完整交互实现。

## 已实现

- Host 支持接收已准备的主题，创建 `YYYY-MM-DD/主题`；重名原子重试 `_2`、`_3`，不复用已存在目录。
- 主题文件名处理、日期目录 realpath 校验、本次运行创建结果授权的空目录回滚；重启后不推测主题目录归属。
- 保留原有接收首条消息后注销工作区、Ungrouped 和旧格式空白回收流程。
- 首次发送协调函数：主题准备 → 目录 → 注册 → Session → 绑定 → 原生发送适配器 → 注销；结果不确定时保留目录和回收保护，后台完成不抢视图。
- 可开关 JSONL 日志，包含 RPC、目录操作、注册、创建、接收、注销和失败事件。
- 注销失败时不删除仍被工作区引用的目录，也不把已接受的消息判定为需要重发。

## 当前限制

原版 rc.2 没有本设计的会话创建前输入和主题准备接入。协调函数导出给后续原生适配器使用，当前选择器没有调用它，因此正常 UI 仍使用原有随机目录流程。

模型主题、预生成标题日志归因、× 常驻入口、持久空项目选择和全部新建／重启路径尚未接入。首次发送测试中的原生标题／Session 回调为模拟；不能据此宣称模型或客户端 e2e 已验证。没有另写主题模型、复制输入框、猴补丁服务或移动执行目录。

## 在实际插件中开启日志

在已安装本地构建版本的插件配置中增加 `debug: true`，保留现有 root：

```yaml
- id: dsh-projectless-session
  config:
    root: 'E:/DSH-Test-Workspace'
    debug: true
```

日志位置为 `<root>/.projectless-session.log`。关闭 `debug` 后不创建日志文件。浏览器开发者工具同时显示带 `[dsh-projectless-session]` 前缀的客户端事件。

```powershell
Get-Content -LiteralPath 'E:/DSH-Test-Workspace/.projectless-session.log' -Tail 50 -Wait
```

字段包括 time、sequence、event，以及对应 rpcId、workspaceId、sessionId、path 或 code。用 ID 和 path 关联各阶段。日志默认不记录原始 prompt、附件内容或凭据；路径本身包含主题和用户名，分享前仍需检查。

日志写入失败只报告一次并停用日志，不影响创建或发送。日志没有轮转，测试完成可关闭 debug 并保留所需记录。

## 本地验证

```powershell
npm run verify
npm run test:trace
npm pack --ignore-scripts
```

- verify 执行类型检查、完整单元测试和构建。
- test:trace 使用真实 Host RPC 和文件系统，加明确标记的模拟原生适配器，保留日志及结果在本仓库 `test-artifacts/trace-*/` 中。它不启动 DSH，不调用模型，不修改用户项目。
- trace 日志首项包含 `SIMULATED_NATIVE_ADAPTER`，结果页说明哪些环节模拟，避免与真正客户端测试混淆。
- pack 生成本地安装包；包版本仍为源码原有 0.6.0，仅作为本地测试包，不代表已经发布。

真正客户端验证还需安装本地包并确认 debug 日志。当前工作不自动替换用户已安装插件。完整主题首次发送和退出重启主线，需要详细设计中的官方接入后才能验收。
