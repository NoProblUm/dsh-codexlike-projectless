## 发布物比较与代码范围

七个受保护模块逐项重新计算哈希：仅 Conversation Client 改变，实际差异是会话 header tooltip；上传 Client、Gateway Client/Host、Session Controller Client、Workspace Client、Session Title Host 六项字节一致。目标哈希来自原版 Desktop，不用 npm 文件替代。

实际使用的十二个 DSH 开发依赖更新为精确 rc.5，导出清单均未改变。对照本地旧 rc.3 npm 包的 lib JavaScript 和声明，仅 Conversation Client 及其 locale 声明变化。部分 npm Client 与 Desktop 内置 Client 字节不同，不能据此宣称两者完全相同。ui-renderer、ui-slots、Workspace、Session 和标题接口的相关声明比较未发现失配。

生产改动限于目标身份、候选/正式版本、Conversation Client 指纹、依赖及用于测试现有校验逻辑的小函数提取。没有新增公开 RPC、配置项或多构建兼容层；未修改草稿、首次发送、上传、标题业务算法和 `startSession` 识别规则。其他 renderSlot 保持原样透传，没有在插件中去除思考签名。

## 自动检查与身份保护

候选执行 `npm ci`、`npm run verify`；本地正式版再次执行 `npm run verify`。两次均为类型检查、88 项测试、构建通过，0 失败、0 跳过。

新增 9 项测试覆盖 clean 精确身份、错误版本/源码 tag/缺失构建号/dirty、七个模块分别缺失或被修改、Host/Client 状态及适配身份不一致。正常字节由原版 Desktop 和冻结包安装核对验证。

真实旧宿主 rc.3 的官方管理器拒绝候选，报告 `incompatible-version` 并恢复原插件，原生项目输入仍可用。这证明管理器层旧版本拒绝；dirty 和逐模块错误的拒绝属于受控测试，未通过修改真实 app.asar 制造变体，也未宣称所有 Host 拒绝分支都运行过真实 Desktop。

包检查独立于 verify：精确文件白名单、MIT/NOTICE、Apache-2.0 第三方许可、入口和类型声明、版本及 engines。候选实际安装的 Host/Client 入口与冻结 tgz 字节一致。正式包同样通过该检查：本地验收包含 15 个文件，Host/Client 和 package.json 与实际安装字节一致；首发 Session 5→6、Workspace 1→1。公开发行包因 README 和报告更新而重新打包，完整校验值以 Release 的 SHA256SUMS 为准，不能沿用本地验收包的哈希。

## 隔离 Desktop 验收

使用官方安装包提取的完整原版应用、独立 DSH_HOME/user-data、官方插件管理器和无密钥 fixture。故障组使用正常退出后复制的独立 profile，每组按自身基线断言。

| 行为 | 实际结果 |
| --- | --- |
| 新建、侧栏和键盘 | keep/append/replace、旧 clearPreviousDraft 优先级、鼠标/键盘侧栏恢复通过；从已发送会话经 Electron 原生 Ctrl+N 恢复符合条件的草稿，保留正文，资源和目录零增量 |
| 首发与并发 | Host Session 仅增加 1，临时 Workspace 回到基线；第一份后台首发不抢回页面、不覆盖第二份草稿 |
| 预设与控件 | standard/minimal blank 匹配通过；真实 UI 只读权限、极简预设、Fixture 模型、附件经 keep、重连和首发保留；标准预设规划模式首发通过 |
| 附件 | 文件/PNG 延迟上传、附件初始化保留、上传失败后的正文/附件保留、原生重试及跨连接恢复通过 |
| 提交前失败 | 模型目录和目录创建失败保留正文，无 Session/Workspace 增量；准备阶段取消不提交 |
| 明确拒绝 | 提交次数 1；正文恢复、Workspace 回收；保留已创建的 Session，未错误要求失败后 Session 零增量 |
| 确认响应丢失 | 原生已接受后丢弃确认，由原生状态对账完成；requestId 有效、提交次数 1，无重复 Session |
| unknown 与提交阶段取消 | 禁止重发并保留不确定资源；unknown 刷新、停用/启用及正常重启后资源数量保持，目录仍存在 |
| 清理 | 注销失败后只重试注销、不重复提交；目录回滚失败锁定草稿；不擅自删除故障注入保留的资源 |
| 标题 | 预生成标题绑定与目录命名通过；fixture 注入标题 provider 失败后使用原生回退标题并成功首发 |
| 运行时释放 | 未知包装被拒绝，随后原生项目初始化可用；停用、启用重启提示、正常重启、卸载和重装通过，持久历史不变 |

Ctrl+N 沿用正式 1.2.0 的既有复用语义，不将“每次必建不同草稿”作为本轮需求。未发送草稿正文和附件仍不跨刷新、重启持久化。

## rc.5 显示与升级

- 五种原始思考输出分别在插件开启、关闭时运行，共 10 组：普通正文、完整签名、签名前缀跨 chunk、未闭合签名、过滤后为空。25ms 周期采集页面流式显示，样本未出现签名前缀或 fixture-secret；展开/折叠、空内容隐藏和刷新历史显示通过。夹具不预先剥离签名。展开交互以宿主“完全展开”设置为明确前置状态；未接入翻译插件。
- 12 组无项目草稿检查覆盖浅深主题、1280/800 宽度、1/1.25/1.5 缩放，正文保留、输入区边界和无横向溢出断言通过。
- 48 组项目 blank/已发送页 × 插件开关 × 相同主题/宽度/缩放组合的原生几何与图标对照通过；短“对话”标签不显示 tooltip，“更多会话视图”固定提示及键盘打开菜单通过。未安装自定义长标签视图扩展，不能将其算作专项通过。
- 已目视检查代表性的窄屏深色草稿及浅色项目开关对照，未声称逐张人工检查全部截图。800 宽、150% 缩放下 hero 内容仍有宿主原生裁剪，插件开关一致。
- rc.3 + 正式 1.2.0 通过 UI 保存根目录并建立持久历史，保留升级前副本；原版 rc.5 打开副本后旧插件标记 incompatible-version，官方管理器更新候选，正常重启后历史与设置保持；新首发 Session 2→3、Workspace 保持 1。
- 复制 profile 后，对 pnpm 的虚拟存储绝对路径元数据进行了测试环境迁移。首次未迁移时的 `ERR_PNPM_UNEXPECTED_VIRTUAL_STORE` 更新失败保留；校正后同一官方管理器更新成功。该结果不等于运行 Windows 安装程序覆盖升级。

## 原始失败与证据

旧脚本迁移曾出现：缺少 fixture 默认模型、未聚焦导致截图超时、过早读取明确拒绝恢复状态、旧固定会话 ID、设置尚未加载即读取空值、默认过程折叠导致找不到可见思考按钮，以及对 Ctrl+N 复用语义的错误断言。均保留原始记录；只校正测试配置、等待条件和既有行为预期，没有为其放宽产品判据或修改业务逻辑。明确拒绝后的提交状态在独立副本单独复测通过。

本机证据目录：`output/rc5-baseline-20261031`、`output/rc5-desktop-20261031`、`output/release-1.3.0-candidate`。正式包及复核记录位于 `output/release-1.3.0`。故障 profile 保留不确定资源用于审计；原版归档、账户状态、完整 profile 和测试模型不进入发行 tgz。

复现入口为 `scripts/acceptance-rc5.mjs`、`scripts/run-rc5-acceptance.mjs`；说明见 `experiments/runtime-acceptance/README.md`。入口核对实际进程 PID、DSH_HOME、可执行文件、版本、完整构建号及 dirty 状态，不凭页面 URL 判断目标。
