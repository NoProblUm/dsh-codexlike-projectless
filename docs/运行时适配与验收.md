# 1.0.0-rc1：运行时适配与验收

日期：2026-10-17。状态：本地自动检查及下述原版 Desktop 验收已通过；CI 与发行资产以对应 GitHub 工作流为准。

## 约定

- 一个市场分发包，Host、Client 与适配代码同版本。新主路径不改写 app.asar 或第三方文件，不维护外部安装助手。
- 目标为 Windows Desktop 0.2.0-rc.2，构建 04f392c9ddd144fa426da2045178797da6db6c11。原版归档 SHA-256：983ca71114e6dfd353fc79af5a1f9481a250ee64c2a3c757673029b811b23bc2。
- 明确无项目后的首次发送前零新增真实 Session、Workspace 和任务目录；未保存选择时保留原生默认项目初始化。有效原生历史优先。
- 草稿仅在当前客户端页面内存活，不承诺关闭、刷新、重启或停用后恢复文本、设置和附件。
- 结果不明时锁住重复首发、保留输入和资源，观察本次原生 requestId 对应的持久用户消息。不以会话非空代替精确接收证据，不自动重发或清扫旧不确定操作。

## 实现与兼容

Host 对五个原版模块做 SHA-256 检查，复用原生标题 provider、路由、结果校验、fallback 与日志绑定。Client 在远程命名空间就绪前安装本地包装；随后核对 Host/Client 适配标识及版本，再启用业务。

原生会话工厂保持定义身份与子插槽所属关系，通过原组件已绑定的 renderSlot 调整本插件草稿的输入参数。原生编辑器、附件注册表、提交状态机继续执行；插件提供统一项目入口，DOM/CSS 仅处理布局与旧入口去重。

Cordis 会代理服务方法，包装归属必须在原实例上检查。释放时只恢复仍归本插件所有的方法及原有属性描述符。服务生命周期结束、部分安装失败及 Session 释放时清理相应包装。未验证的新建接管组合会阻止无项目核心流程，不争抢方法。

已发现并修正两处原有假设：rc.2 的传输失败是 gateway/internal；原生 /plan 的参数是消息而不是 on 开关，且 commands.execute 的空结果表示未匹配。现在按真实结果决定是否发送。

## 证据边界

- 故障和延迟由隔离测试实例的 RPC 边界注入，不写入产品代码。此前浏览器网络拦截不适用于 dsh-app 协议，已撤销；不计作通过证据。
- 未验证 macOS、Linux、其他 Desktop 构建、外部模型服务及 Git Graph 等接管组合。规划仅对支持该命令的预设生效；不支持的设置在发送前明确报错。
- 单元检查覆盖包装归属、属性描述符恢复和取消检查点；不把这些结果称为所有第三方冲突及所有服务重建场景的真实宿主验收。

诊断程序位于 experiments/runtime-adapter-probe、experiments/runtime-acceptance 及 scripts/probe-runtime-*.mjs；测试产物位于被忽略的 output/。历史归档补丁和恢复脚本保留为验证基线，不进入新的市场包。
